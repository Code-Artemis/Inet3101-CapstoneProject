# Inet3101-CapstoneProject

Problem Statement: For my capstone project, I created a calendar management system. This system/application allows users, like me, to create, view, update, and delete calendar events, as well as track scheduling conflicts and support daily and weekly events. Calendar information can be shared through a TCP server connection, while events are saved to a binary file, allowing users to access appointments after closing and reopening the application.

Design & Architecture Details: The calendar management system uses a multi-file C architecture, separating the functions. I created Event and Recurrence structs that store information such as appointments, including event ID’s, dates, times, titles, and recurrence settings. A pointer-based linked list called EventStore was created to manage events continuously using malloc() and free(). I used file I/O functions such as fopen(), fread(), and fwrite() to save and load events from events.dat, which allows for data persistence. To provide basic concurrency protection during file operations, I chose to use flock() with shared and exclusive locks. For the networking aspect, I implemented a TCP server and client using C socket functions. The server listens on port 8080 and sends saved calendar information to clients connecting through 127.0.0.1. The client then receives the event information and displays it in the terminal. A Makefile was created to compile the application, server, and client.

Pros & Cons of Solution: Like any system, there are advantages and disadvantages. One advantage of my system is its ease of use and that it does not require an external database. The use of a linked list allows events to be added and removed continuously without allocating a fixed-size array. The system also saves events between sessions and checks for scheduling conflicts and recurring appointments. However, there are limitations. Searching for events means reviewing the linked list, which can become slower as more events are added. The system rewrites the binary file when saving changes, which is neither helpful nor efficient. File locking, although helpful for protecting file operations and separating processes, can still overwrite changes made from older copies of the calendar. Another disadvantage is that the TCP server can only handle one client at a time rather than multiple clients simultaneously. Efficient event searching and stronger concurrency controls could improve support for multiple clients.

AI Audit Reflection: 
Throughout my capstone project, I used ChatGPT to help develop, review, and troubleshoot my Calendar Management System. I asked it how to organize my header files, struct definitions, and linked list ADT. For example, I asked AI to help review how my EventStore should manage continuously allocated memory and how my system should separate event management, file persistence, and TCP networking. I also used AI to audit my code for potential memory leaks, buffer overflows, file-handling errors, and concurrency issues. ChatGPT suggested using flock() to protect file operations and adding a signal handler so the TCP server could shut down properly. 

To verify memory management, I ran Valgrind on the calendar management system as well as the TCP server, which reported no memory errors and did not detect any memory leaks. I also tested file locking by running two processes and confirmed that the calendar waited until the exclusive lock was released. However, ChatGPT was unable to identify every issue during the initial development. For example, the original conflict detection function only checked events that were on the same date and did not account for recurring appointments. The file-loading function also initially failed to detect incomplete records. I made additional changes and tested both features. 

Overall, AI was helpful for reviewing my program's architecture and identifying potential problems, but I learned that AI-generated code is not always complete or accurate. I verified the changes by compiling my program with GCC and testing its functionality rather than relying only on AI suggestions.
